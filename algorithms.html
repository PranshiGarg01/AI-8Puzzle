REFERENCE / CONCEPTS

THE SEARCH CODEX.

Six algorithms and two heuristics used by this 8-Puzzle solver.

01 · Breadth-First Search

UNINFORMED · QUEUE

Explores states by increasing depth. It is complete and finds a shortest path for equal-cost moves, but can use substantial memory.

Frontier: FIFO queue

02 · Depth-First Search

UNINFORMED · STACK

Follows one branch deeply before backtracking. It can use less frontier memory, but does not guarantee the shortest path.

Frontier: LIFO stack

03 · Depth-Limited Search

UNINFORMED · DEPTH CAP

A DFS variant that stops expanding at a selected depth limit. It can miss solutions deeper than the cap.

Depth ≤ limit

04 · Iterative Deepening DFS

REPEATED DLS

Repeats depth-limited search with limits 0, 1, 2, and onward. It revisits shallow states but can find a shallowest solution with low memory use.

Limits: 0 → 1 → 2 → …

05 · Greedy Best-First Search

INFORMED · HEURISTIC

Prioritizes the frontier state with the smallest heuristic estimate. It may be quick, but does not guarantee an optimal path.

Priority: h(n)

06 · A* Search

INFORMED · PATH + HEURISTIC

Balances path cost already paid and estimated remaining cost. With unit-cost moves and either heuristic below, A* finds an optimal solution.

f(n) = g(n) + h(n)

HEURISTICS

Estimate the distance

Misplaced Tiles

Count numbered tiles that are not in their goal positions. Ignore the blank. It is simple and admissible.

h(n) = number of misplaced numbered tiles

Manhattan Distance

For each numbered tile, add its horizontal and vertical distance to its goal cell. Ignore the blank.

h(n) = Σ (|row − goalRow| + |col − goalCol|)

LIMITATIONS

Understand the trade-offs

  • All moves have equal cost in this implementation.
  • BFS and informed search can consume substantial memory on difficult states, so safety limits are used.
  • DFS and GBFS do not guarantee shortest paths.
  • DLS and IDDFS may stop at the chosen depth limit.
  • Runtime depends on the browser, device, and test puzzle.
